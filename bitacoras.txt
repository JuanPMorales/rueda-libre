RAZON DEL USO DE FLEX Y GRID EN LOS ULTIMOS 5 COMMITS
======================================================

1. formulario con dos campos en la misma fila
    Se utilizo display: flex en .parejas para colocar el tipo y numero de
    documento junto al celular. flex-wrap permite que los campos bajen a otra
    linea cuando el ancho de la pantalla no es suficiente, y flex: 1 reparte
    el espacio disponible entre las dos columnas.

2. formulario de reserva en grid 2:1
    Se utilizo display: grid en .formulario-informacion para separar el
    formulario y el horario de atencion en dos columnas. La relacion 2fr 1fr
    da mas espacio al formulario que al horario, mientras gap mantiene una
    separacion uniforme.

3. tarjetas de Nuestras rutas
    Se utilizo display: grid en .Nuestras-rutas para distribuir las tarjetas
    en columnas responsivas con repeat(auto-fit, minmax(...)). Asi las tarjetas
    se acomodan automaticamente segun el ancho disponible. Se utilizo display:
    flex en .tarjetas para ordenar verticalmente la imagen, el texto y el
    enlace; margin-top: auto mantiene los enlaces alineados al final.

4. portada de bienvenida
    Se utilizo display: grid en .seccion-portada para organizar el texto de
    bienvenida y la imagen en columnas responsivas. auto-fit y minmax permiten
    que ambas partes se adapten a distintos tamanos de pantalla sin fijar una
    cantidad de columnas.

BITÁCORA DE PRUEBAS RESPONSIVE

1. RESOLUCIÓN: 360 PX
Problema: La tabla presentaba problemas de visualización y desbordamiento horizontal.
Solución: Se aplicó la propiedad CSS border-collapse: collapse; para unir los bordes de las celdas y mejorar la presentación de la tabla.

2. RESOLUCIÓN: 360 PX
Problema: Los cuatro elementos del footer aparecían demasiado juntos, afectando la distribución del contenido.
Solución: Se agregaron las siguientes propiedades CSS dentro del media query:

display: flex;
flex-wrap: wrap;
justify-content: space-around;
gap: var(--espaciado-mediano);
align-items: center;

3. RESOLUCIÓN: 768 PX EN ADELANTE
Problema: Los elementos del header aparecían centrados y no tenían una distribución adecuada.
Solución: Se agregó la propiedad CSS justify-content: space-between; dentro del media query para distribuir correctamente los elementos del encabezado.

CONCLUSIÓN:

Se realizaron pruebas de visualización en diferentes resoluciones para identificar problemas de diseño responsive. Se ajustaron las propiedades CSS mediante media queries y Flexbox para mejorar la distribución de los elementos y garantizar una mejor adaptación a diferentes tamaños de pantalla.

=======================
CLASES DE BOOTSTRAP
=======================

1. rounded:
   Redondea las esquinas de un elemento, como imágenes, tarjetas o contenedores.

2. img-fluid:
   Hace que una imagen sea adaptable al tamaño de su contenedor, evitando que se desborde.

3. g-3:
   Agrega un espacio de separación (gutter) entre las columnas y filas de una cuadrícula de Bootstrap.

4. ratio-4x3:
   Establece una proporción de aspecto de 4:3 para un elemento, como una imagen o un video.

5. ratio:
   Permite mantener una proporción de aspecto determinada en un contenedor, ayudando a conservar sus dimensiones relativas.

CONFLICTOS ENTRE ESTILOS PROPIOS Y BOOTSTRAP

1. Alineación de títulos: text-center vs. regla global de encabezados

En los títulos de las secciones “Bicicletas” y “¿Por qué Rueda Libre?” se agregó la clase de Bootstrap `text-center`. Sin embargo, en styles.css ya existe una regla global para h1, h2, h3, h4, h5 y h6 que aplica `text-align: center`.

Solución: quitar la clase `text-center` de esos títulos si se desea mantener la alineación central desde la hoja de estilos propia. Es un mismo conflicto repetido en dos elementos, no dos conflictos diferentes.

2. Peso de la fuente: fw-semibold vs. regla global de encabezados

El título “¿Por qué Rueda Libre?” usa la clase `fw-semibold`, que establece un peso de fuente seminegrita. La regla global de encabezados en styles.css establece `font-weight: 700`.

Solución: quitar `fw-semibold` si se quiere que los encabezados mantengan el peso definido en styles.css. Si se conserva, Bootstrap prevalece para ese elemento.

NOTA:
Los dos casos anteriores son conflictos identificados en el código revisado y en DevTools

| Aspecto | v1.5: CSS propio | Actual: CSS propio + Bootstrap |
|---|---|---|
| Control visual | Alto control sobre colores, espacios, tamaños, tarjetas y formularios. | Se conserva la identidad visual, pero algunas reglas dependen de Bootstrap. |
| Responsive | Requirió media queries y ajustes manuales. | Bootstrap facilita la adaptación mediante `container`, `row`, `col-*` y utilidades. |
| Cantidad de CSS | 333 líneas y más reglas específicas. | 230 líneas; se redujo código repetido para la estructura de páginas. |
| Rapidez de desarrollo | Más lenta porque cada comportamiento se escribía manualmente. | Más rápida para grids, espaciado y distribución de formularios. |
| Mantenimiento | Selectores propios fáciles de localizar, pero numerosos. | Menos CSS propio, aunque hay que revisar conflictos entre Bootstrap y `styles.css`. |

Ventajas de v1.5:

- Permitio definir con precision la apariencia y el comportamiento
  responsive de cada componente.
- El diseno dependia menos de clases externas.
- Las dimensiones de las imagenes, tarjetas y espacios eran mas faciles
  de controlar desde un solo archivo.

Desventajas de v1.5:

- Se necesitaba escribir y probar mas reglas CSS.
- Los cambios responsive exigian media queries y ajustes manuales.
- La estructura de formularios y tarjetas podia requerir mas tiempo.

Ventajas de la version actual:

- Bootstrap acelera la creacion de filas, columnas, gutters y espaciados.
- Se redujo la cantidad de CSS que debe mantenerse manualmente.
- La estructura de reservas se adapta mejor a distintos tamaños de pantalla.

Desventajas de la version actual:

- Pueden aparecer conflictos de especificidad entre Bootstrap y
  styles.css, como `text-center` o `fw-semibold`.
- Algunas decisiones visuales quedan condicionadas por las clases
  disponibles en Bootstrap.
- Para conservar una apariencia consistente se deben revisar ambas
  fuentes de estilos.

3. CONCLUSION
------------------------------------------------------------

La v1.5 ofrecio mayor control y personalizacion, pero requirio mas
codigo y mas tiempo de ajuste. La version actual redujo styles.css de
333 a 230 lineas y agilizo la construccion responsive de reservas
gracias a Bootstrap. La mejor solucion fue combinar ambas estrategias:
Bootstrap para la estructura repetitiva y el responsive, y CSS propio
para la identidad visual.
